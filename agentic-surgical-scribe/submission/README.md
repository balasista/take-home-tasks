# submission/

Put anything here that is not code and not the write-up. Organize the repo
however you prefer, as long as it is easy to find and easy to run.

Suggested contents:

- `eval/`: your evaluation harness output, per-case results, the summary
  numbers, and the failure cases you found
- `fixtures/`: the recorded LLM responses that back your `--mock` mode
- `prompts/`: if you version prompts as files rather than in code
- `traces/`: a sample run trace, if your architecture produces one
- `out/`: example output produced from `data/sample_case/`
- notebooks, error analysis, figures, all optional but welcome

Your **design write-up** belongs in this task's `README.md`, one level up:
architecture, the options you rejected and why, eval results, known failure
modes, cost and latency per note, and what you would do with a month.
